## Permanent-complexity admission

Order considered: delete -> simplify -> reuse -> extend -> create. Reuse upstream grammy, ws, pairing and chunking; extend its local state rather than introduce a database or hosted service. The exact added durable surfaces are `src/store.ts` (runtime dispatch/delivery journal) and the `codex-telegram-bridge.service` user unit generated by `src/setup.ts`. They replace the proposed new Python bridge and the upstream unmanaged launcher. Qualification demonstrated replay and shared-daemon lifecycle failures that the original state file and launcher could not handle. Carrying cost is one private local journal, one process, Node/dependency updates and protocol regression tests. Remove the service and journal when Telegram control is retired; uninstall preserves the journal until an operator explicitly chooses to remove it. No new agent role, scheduler, cloud resource or Nullsignal governance is introduced.
