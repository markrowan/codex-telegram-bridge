# Validation

An opt-in disposable-daemon proof passed seven behaviors: reply relay, inherited settings, immediate steering with harmless command approval, interruption, approval resolved by a second client, replies initiated by a second client, and structured questions. The proof grants only an exact harmless printf command. It creates its own disposable conversation and stores receipts outside the repository.

Run local checks with `npm run check` and `npm test`. Run `node scripts/prove-daemon.mjs` only when explicitly authorizing disposable-thread creation and its harmless approval probe on a local Codex daemon.

Real Telegram acceptance remains required after private local token entry: pairing, thread switching, watched ChatGPT activity, project selection, questions and approval cards, long replies, unauthorized account rejection, and service restart recovery. Unit and daemon proofs do not establish Telegram end-to-end readiness. The installer leaves the user service inactive and disabled.
